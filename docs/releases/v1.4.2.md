# AI 输入助手 v1.4.2

- 修复组合输入检测失败后不再复查导致的“等待选词”停滞；等待期间约每 750 毫秒重读，暂停或切换目标会取消等待。不会在仍有明确组合输入时按超时放行。
- UIA 组合范围须包含文字、处于当前文档并关联当前光标或选区，忽略其他位置遗留的组合范围；原生 IMM 检测继续保留。
- 自动思考对文本使用 low，对截图使用 high，不因上下文字数多而提高强度。Max、不思考仍显式保留；思考模式继续使用服务默认生成预算，不用缩小总 token 上限来提速。
- 重写续写提示词：充分展开相关内容再收束，避免长原文只得到空泛总结；有后文时优先衔接，允许短补全。输入选区与完整正文不裁剪。
- 状态浮窗显示等待响应、思考、生成正文和耗时；明确区分达到输出上限与普通中断，失败仍只显示状态。
- 增加不含正文的生成诊断，包括耗时、首个正文分片、字符数、结束原因和 token 用量。

已通过 [Windows 构建 #35222759656](https://github.com/arcxya09/ai-input-assistant-windows/actions/runs/35222759656)，安装附件来自源码提交 `bfcee673334a7d47103bb0868bf6406594515cdf`。

- 110 项核心测试通过：组合范围与光标／选区边界、自动 low／截图 high／Max／不思考请求、长选区完整发送、长思考流后的完整正文、阶段与用量统计、输出上限单独报错。
- WinUI 冒烟检查通过：等待选词后重新安排检测、持续等待仍可复查、暂停取消及迟到状态不恢复浮窗；保留后台关闭恢复、字号、DPI、焦点与长预览检查。
- 原生 Windows、Edge、Obsidian 1.13.7 实时预览及源码模式的光标插入、短选区、跨段落正反向选区与剪贴板回归通过。
- 真实 GitHub 附件下载校验和 4 项更新安装检查通过，设置、密钥保留。

构建机没有真实中文键盘布局，候选词输入法实测明确跳过。此次验证证明状态复查和范围判断逻辑，并不代表所有输入法／文本框已验收；用户所用输入法与具体文本框仍需实机确认。没有进行真实付费模型测试，不宣称延迟或输出长度达到固定指标。

接口依据：[DeepSeek 请求参数](https://api-docs.deepseek.com/api/create-chat-completion/)：支持 none／low／high／max，默认 high；思考模式默认生成预算为 64K，Max 为 128K。low 控制思考强度，不保证固定响应时间。
