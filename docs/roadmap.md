# 开发路线

当前阶段：软件工程技术方案 v0.1 已完成。实际编码、Windows 原型和真实 API 验证尚未开始。

## 已完成

- [产品需求基线](requirements.md)。
- [技术方案](architecture.md)：模块、状态机、上下文读取、插入、模型、截图、数据与部署设计。
- [验收矩阵](acceptance.md)：平台、目标控件、竞态、输入法、数据生命周期与发布标准。
- 官方资料核查：当前 deepseek-flash 支持图像理解，可显式关闭思考模式。

## M0：工程与关键系统原型（下一步）

- 建立 C# / .NET 10 / WinUI 3 解决方案，核实 Windows App SDK 稳定版的实际包号并锁定依赖。
- 开发 ContextHost 和 ContextProbe，验证光标、前后文、密码属性及中文组合输入。
- 验证无焦点浮窗、三组快捷键和 Unicode 插入／回读。
- 在 Win10/11 核验自包含部署与依赖，逐项记录支持控件和失败原因。
- 退出条件：技术方案 M0 项与验收矩阵相关用例具有实际证据。

## M1：文本续写闭环

- 实现 API Key 设置、暂停／启用、1.5 秒触发、建议展示与逐条采纳。
- 实现请求版本校验、焦点变化取消、插入确认与下一条生成。
- 模拟服务验证错误／乱序／断流；具备测试 Key 后验证官方真实文本请求。

## M2：一次性截图

- 实现输入窗口所在显示器捕获、图片请求、上传后清理。
- 验证暂停下单次调用、失败清理、后续续写无图片复用。
- 验证官方真实图片请求和小字可读性。

## M3：兼容性与交付

- 完成 Windows 10/11、中文输入法、目标应用和多显示器验收。
- 完成日志导出、干净系统部署、ZIP、每用户安装包和使用说明。
- 通过发布阻断项后再发布可运行版本。

详细交付物和退出条件以技术方案、验收矩阵为准。文档完成、构建通过和真实桌面验收分别记录。
